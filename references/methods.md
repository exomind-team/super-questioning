# 问题转化三法详解

> 本文件为 super-questioning skill 的参考文件，补充问题质量预诊三法的详细操作示例。

---

## 方法一：L1具体化原则（叶修）

**背景**：问题抽象到无法回答，或缺乏任何背景信息。

**操作**：添加充分背景信息
- 时间线：这个问题经历了怎样的演变？
- 数字：具体数据/规模/频率是多少？
- 场景：典型场景是什么？何时何地发生？
- 已尝试：之前试过什么方法？效果如何？

**示例**：

| 原始问题 | 转化后问题 |
|---------|---------|
| 该怎么办 | 我的情况：[背景描述，包括时间线/数据/已尝试方法] 具体困境：[精确描述，不是抽象的'学不好'，而是具体场景] 我想问的是：[一个具体的、可以回答的问题] |
| 产品不好用 | 这个问题在什么时候出现？（加载慢/特定操作/特定用户）持续多久了？（一直/最近才出现）你已经试过什么方法？（换设备/清除缓存/重装） |

---

## 方法二：差异性发问（汤质）

**背景**：问题过于泛泛，AI给出的回答是「正确的废话」。

**核心原则**：好问题应面向「差异」而非「过程」。

**操作**：

1. **找差异**：列出同一现象在不同情境中的不同表现
2. **问差异**：用「为什么」而非「是什么」发问
3. **多维分解**：从多个维度分析差异根源
4. **回到本质**：用新概念命名这个差异

**示例**：

| 泛泛问题 | 差异问题 |
|---------|---------|
| 土地改革是怎么发生的？ | 为什么土地改革在福建针对宗祠而非地主？为什么江南小土地出租者较多？ |
| 这个功能怎么实现？ | 在性能优先和开发速度优先这两个维度上，这个功能的权衡点分别在哪？ |
| 要不要上这个技术？ | 这个技术在什么规模下会从优势变成劣势？ |

## 方法三：辩证逆转（汤质）

**背景**：问题预设「X是障碍」，答案被困在常识框架内。

**核心操作**：把「如何克服X」翻转为「X如何成为条件」。

**示例对照**：

| 常识问题 | 逆转问题 |
|---------|---------|
| 如何克服紧张？ | 紧张如何让我们表现得更好？ |
| 如何减少拖延？ | 拖延如何帮助我们做出更成熟的决策？ |
| 如何避免团队分歧？ | 团队分歧在什么条件下能成为决策质量的保障？ |
| 如何克服沟通障碍？ | 沟通障碍的存在，揭示了我们忽略了谁的视角？ |
| 如何减少用户流失？ | 用户流失在什么意义上是一种反馈，而不是损失？ |

**应用场景**：当人问「如何克服X」时，Agent示范用辩证逆转重构问题，引导人跳出二元对立思维。
