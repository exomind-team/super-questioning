# 下一轮计划：从行为稳定性到真人认知协作

日期：2026-10-18。状态：草案，供 ChatGPT Web 复核。

## 目标与边界

下一轮不增加认知路由，也不把“用户应该学会元认知”写成 Skill 的硬性要求。研究分两条主线：

1. **系统可靠性**：确认 Skill 激活、文件操作和结果回报是否可复现，区分 Skill 指令问题与宿主/工具问题。
2. **认知协作质量**：确认真人用户的问题理解是否因对话而发生有依据、由用户认可的变化；另将迁移能力作为长期探索假说。

先完成可靠性归因，再招募参与者。v5.7.0、0.6.0、0.6.1 已测试提交保持不变。若出现可重复且可归因的缺陷，再另开 0.6.2 候选；不要用一次运行异常直接追加 SKILL 规则。

## 第 0 阶段：修正评测记录（立即完成）

- 实际矩阵是 3 个版本 × 6 个场景 × 每格 1 次 = **18 次**；每个场景跨版本共 3 次，不是每个版本每场景 3 次。
- 修正 0.6.1 分项：5+9+10+10+6+10=**50/54**。创意场景使用校正盲评分的 10/10，不能沿用初次评分包里的 7/10。
- 保留初次评分与校正评分的差异说明，不覆盖历史记录；此交接的主结果采用第二位无上下文评分者的校正评分。
- 将原始对话记录、分项分数与评分依据逐项绑定，避免再次靠摘要重建。

## 主线 A：系统可靠性

### A1. 交叉 Skill 激活归因

**问题：** 两个会话出现了未由用户触发的 ENTP 模式声明，分别发生在 v5.7.0 与 0.6.1。现在不能确定这是实际加载了其他 Skill、模型借用了相似话语，还是宿主注册表路由造成。

**设计：**

- 对照条件：仅注册被测 Skill 的隔离环境；当前完整全局 Skill 注册表环境。若无法创建真实隔离环境，就标记“隔离条件未实现”，不把提示词中要求忽略其他 Skill 当作隔离。
- 版本：v5.7.0 与 0.6.1；保持模型、触发语和工具权限一致。
- 场景：视觉作品评鉴、证据争议、普通开放探究三种。
- 重复：每个版本 × 注册表条件 × 场景至少 2 次；若出现差异，再增至 3 次。
- 每次记录：实际加载 Skill ID/路径与时间（如宿主可观测）、原始用户输入、完整输出、是否出现未触发的模式声明。若无加载日志，只能记作“出现交叉模式话语”，不能断言另一个 Skill 确实已加载。

**判读：**若只在完整注册表出现且加载记录确认，优先改进宿主技能隔离/路由；若隔离条件也稳定出现，再考虑 Skill 的触发边界文本。

### A2. 写后核验与回报一致性

**问题：** 一次 0.6.1 执行先发生路径检查错误，之后目标文件正确，但回复链接漏了试次路径；另一次报告没有写后回读，尽管外部检查证明结果正确。

**设计：**对已授权、范围单一的小文件编辑，比较 v5.7.0、0.6.0、0.6.1；覆盖同消息授权与已成熟决策两种输入，每格至少 2 次。使用独立临时目录。

**逐项核对：**目标路径、文件内容、范围外文件是否变化、写后是否回读、最终回复链接是否指向实际目标、未核验时是否如实保留不确定。任何未授权写入都是硬失败；目标正确但链接错误要单独记为回报失真。

### A3. 记录与评分链

- 评分前保存逐轮原始对话及工具调用输出，正文与摘要分开。
- 每项分数必须附对话证据位置/短引文；总分由表格或脚本计算，人工复核总和。
- 评审者看匿名记录；映射在评分锁定后揭盲。
- 把“实际加载 Skill”“出现某模式措辞”“符合某类行为”设为三个不同字段。

## 主线 B：真人认知协作小试验

### 研究问题

在真实任务中，0.6.1 是否比 v5.7.0 更能帮助用户形成**具体、可追溯、由用户认可**的问题理解变化？问题表述听起来更深刻不算成功；用户必须能指出变化依据，并能说明仍有哪些未知。

### 初步设计

- 参与者：先做 6–8 人的探索性小样本，不声称统计代表性。
- 版本：v5.7.0 与 0.6.1，顺序在参与者间平衡；使用同一模型和工具条件。0.6.0 暂不加入真人试验，除非工程可靠性结果显示需要区分它与 0.6.1。
- 场景：①真实产品/UI 需求；②参与者提供的真实视觉作品；③开放探索或创造性辩论。优先由参与者选安全、可脱敏的材料，不把内部资料上传到公开仓库。
- 每次对话前，参与者用自己的话写下初始问题、当前猜测、信心和想采取的下一步；对话后不让 AI 代答，先请参与者独立写出当前问题定义、依据、未知和下一步。
- 对话结束后记录：用户是否认可 AI 的重构、是否感到被引导/被替代、信息负担、决策归属，以及实际下一步是否改变。
- 评分者查看完整匿名对话和用户的独立前后陈述，至少两名人类评审对关键样本评分；LLM 评分只作辅助。

### 主要与次要观察指标

**主要指标：问题理解的有据变化。** 看用户自己的问题表述是否更具体、是否能指回支撑它的经历/证据、是否区分事实与假设、是否明确下一步能验证什么。若用户有理据地拒绝 AI 提议的新定义，也可以是良好结果。

**次要指标：**动作选择是否恰当（问/查/做/反馈）、无效追问回合、用户感受到的认知负担与自主权、是否形成可执行的下一步。不得把提问数量或 R 编号命中率作为主要成效。

## 迁移能力：长期假说，非本轮硬门槛

可在 1–2 周后给用户一个新的、结构相似但内容不同的任务，不启用 `super-questioning`，观察用户是否能自行描述卡点、区分证据与假设、选择下一种认知动作。一次前后对比只能形成线索，不能证明能力增长来自 Skill；需记录任务差异、练习效应和间隔。此阶段不要求 Agent 教用户术语或公开元认知检查表。

## 版本决策门

- 若 ENTP 声明只在非隔离环境出现，先修宿主路由，不改核心 Skill。
- 若交叉模式在隔离环境重复出现，再对触发边界做最小修订并针对性复测。
- 若写后回报不一致重复出现，优先检查工具/执行编排；只有确认是 Skill 指令造成的再修 SKILL.md。
- 若 0.6.0 与 0.6.1 的行为无法区分，选择更短、更清楚、维护成本更低的一版，而不是按一次总分排名。
- 只有真人试验显示用户的问题理解更准确、依据更清晰且自主权未下降，才考虑把认知路由作为稳定版本基础。
